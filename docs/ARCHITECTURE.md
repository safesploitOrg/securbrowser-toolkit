# Architecture

## Deployment boundary

Only `public/` is deployed.

```text
Repository
├── public/                         <-- static hosting root
│   ├── index.html
│   ├── assets/
│   │   ├── css/app.css
│   │   └── js/
│   └── vendor/sevenzip-wasm/      <-- generated by build:public
├── tests/
├── scripts/
├── docs/
└── .github/
```

The original root `index.html` and root `assets/` must not exist. `npm run layout:check` enforces this.

## Secure File

```text
app.js
  |
  +--> file-utils.js
  |
  +--> encryption.js
          |
          +--> crypto.js
          |     +-- PBKDF2-HMAC-SHA512
          |     +-- AES-256-GCM
          |
          +--> file-format.js
                +-- v2 encode/decode
                +-- legacy format detection
```

Cryptographic modules do not manipulate the DOM, keeping the core independently testable.

## Secure Archive

```text
app.js
  |
  +--> archive-utils.js
  |
  +--> archive.js
          |
          +-- classic Web Worker
                 archive-worker.js
                    |
                    +--> /public/vendor/sevenzip-wasm/sevenzip-wasm.js
                    |          |
                    |          +--> sevenzip-wasm.wasm
                    |
                    +--> isolated Emscripten virtual filesystem
```

The main thread handles selection, validation, progress and browser downloads. Compression, encryption, listing and extraction happen in a dedicated worker so 7-Zip work cannot block normal UI interaction.

A fresh sevenzip-wasm instance is created for logically separate commands such as creation, verification, metadata inspection and extraction. This keeps command lifecycles isolated rather than reusing mutable Emscripten process state.

## Data flows

### Secure File encryption

```text
File --> ArrayBuffer --> PBKDF2-SHA512 --> AES-GCM --> v2 envelope --> Blob URL
                         ^
                         |
                    passphrase
```

### Secure Archive creation

```text
Files/folder
    |
    v
Worker virtual FS
    |
    v
7-Zip: a -t7z -mhe=on -p...
    |
    v
archive.7z
    |
    +--> fresh 7-Zip runtime tests with password
    +--> fresh 7-Zip runtime proves listing fails with a wrong password
    |
    v
Blob URL/download
```

### Secure Archive extraction

```text
.7z + passphrase
    |
    +--> 7z signature check
    +--> list/preflight path + expansion checks
    +--> fail closed if metadata listing exceeds inspection budget
    +--> extract to worker virtual /out
    +--> collect regular files only
    +--> re-check output limits
    |
    v
Blob URLs / optional explicit directory save
```

## Runtime dependencies

Secure File has no third-party runtime cryptographic library.

Secure Archive relies on pinned sevenzip-wasm 26.3.0 / 7-Zip 26.03. The build downloads one fixed immutable GitHub release archive, verifies its SHA-256, extracts the runtime into `public/vendor/sevenzip-wasm/`, and deploys those files from the same origin. The running application never loads archive code from a public CDN.

npm production `dependencies` remains empty; npm packages in this repository are development tooling only.
